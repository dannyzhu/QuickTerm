## QuickTerm 1.5.1

Universal binary (Apple Silicon + Intel, macOS 15+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

### Highlights
- **Pane close animation**: closing a pane now fades it out over 0.28s, mirroring creation. In dwindle the sibling grows smoothly into the freed space; in scrolling and for floating panes the pane fades and the strip re-flows. Layout actions, workspace switches and quit confirmation always act on the real layout (pending closes are flushed first). Honors *Reduce motion*.
- **Dwindle close focus**: after closing a pane, focus goes to the nearest pane of the sibling subtree that takes over its space (Hyprland semantics: next, otherwise previous) instead of the first pane.
- **Dwindle new pane**: split direction follows the focused pane's on-screen aspect (wider → split right, taller → split below); a local shrink/reveal animation replaces the full-tree rebuild; the new pane is focused.
- **Unified pane gap**: one config key `pane-gap` (per-side padding in pt, default 5, 0–20) applies to scrolling, dwindle and floating panes alike; neighbours are exactly 2×gap apart in both layouts (the dwindle divider line no longer takes layout space). `dwindle-gap` is still read as a legacy alias. The scrolling peek grows with the gap so the neighbour's border stays visible.

### Fixes
- Crash: engine callbacks could reach an already-freed pane view (dangling `userdata` from libghostty's asynchronous surface free) — now freed synchronously with a live-view registry guard.
- A pane whose shell exits while its workspace is in the background is now removed (it used to linger as a dead surface).
- Scrolling columns keep a stable identity when their first pane closes or a pane is drag-reordered (no more blank frame / focus reset).
- Focus hand-off during concurrent closes never lands on a fading pane; the close-confirmation dialog no longer runs inside the engine callback.

## QuickTerm 1.5.1（中文）

通用二进制（Apple Silicon + Intel，macOS 15+），ad-hoc 签名，首次打开请按 README「安装」一节处理 Gatekeeper。

### 亮点
- **关闭 pane 动效**：关闭时 0.28s 渐隐，与创建对称。dwindle 下兄弟 pane 平滑长满腾出的空间；scrolling 与浮动 pane 渐隐后重排。布局操作、切换工作区、退出确认之前先把淡出中的 pane 立即移除，始终作用于真实布局；遵循系统「减弱动态效果」。
- **dwindle 关闭焦点**：焦点交给接管其空间的兄弟子树中最近的 pane（Hyprland 语义：下一个，否则上一个），不再回到第一个 pane。
- **dwindle 新建**：按焦点 pane 的实际长宽决定方向（横向宽则右侧、纵向高则下方）；局部收缩/揭开动效取代整树重建；新 pane 获得焦点。
- **统一留白**：一个配置键 `pane-gap`（每边留白 pt，默认 5，0–20）同时作用于 scrolling、dwindle 与浮动 pane；两种布局的相邻间距都恰好是 2×gap（dwindle 分隔线不再占布局空间）。旧键 `dwindle-gap` 仍可读作别名。scrolling 露边随留白增大，邻列边框始终可见。

### 修复
- 崩溃：引擎回调可能触及已释放的 pane 视图（libghostty 异步释放 surface 留下悬垂 userdata）——改为同步释放并加存活视图登记表守卫。
- 后台工作区里 shell 退出的 pane 现在会被移除（原先残留为死 surface）。
- scrolling 列在列首 pane 关闭或拖拽换位时保持稳定身份（不再闪一帧、焦点重置）。
- 并发关闭时焦点不会交给正在消失的 pane；关闭确认对话框不再运行在引擎回调栈内。
