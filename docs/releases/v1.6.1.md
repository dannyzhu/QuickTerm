## QuickTerm 1.6.1

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

One headline: QuickTerm now **knows what the AI agent in each pane is doing, and asks for you only when a human is needed**. Run Claude Code, Codex and Gemini CLI in as many panes as you like; the one that stops for an approval lights up its pane, its workspace pill and the Dock, and sends a system notification — then all of it clears when you answer.

### Agent awareness
- **The agents report their own state.** QuickTerm installs a hook into the agent's own lifecycle-hook system (`quickterm hooks install claude-code | codex | gemini`, or say yes the first time a pane is seen running one). Claude Code's `PermissionRequest`, `Notification`, `Stop` and `StopFailure`, Codex's `PermissionRequest` and `Stop`, Gemini's `Notification` and `AfterAgent` become exact states: idle, working (thinking or the tool being run), blocked on an approval / a choice / input, done, failed. Nothing is read off the screen.
- **An info strip on the pane** shows the agent, its state and its own message — drawn inside the pane's top padding, so the terminal is never resized and a running TUI never reflows. `[agents] info-strip = false` hides it.
- **The hook cannot hurt the agent.** It is one shell script that bakes in the absolute path of the bundled CLI (it never trusts an environment variable to choose what runs), exits 0 with no output in every situation — outside QuickTerm, socket gone, a megabyte on stdin — and reports through a new `report` command class that needs no consent, cannot be blocked by a QuickTerm dialog, has its own rate limit, and must carry the pane's own token, so a process can only ever describe the pane it lives in. Installing is the one thing that asks, once per agent; `hooks uninstall` removes exactly what was written.
- **Agents are data.** `Resources/agents/<id>.toml` maps hook events and notification text to states; your own rule files in `~/.config/quickterm/agents/` add or override an agent without code.
- `quickterm agents list`, `agent.state.changed` on the event stream, and `state --json` carry the agent's state per pane, so an orchestrating agent can ask which panes need a human before asking the human.

### Notification center
- A general service any feature posts into: one notice per pane and source, needs-user or info, resolved when the state that raised it changes, when you type into the pane, when you acknowledge it (`quickterm notices ack`), or when the pane closes — never on a timer.
- Six ways it shows: a macOS notification (only while the pane is not active; a click takes you to the pane and is navigation, not acknowledgement), the Dock badge, a red mark on the pane frame, a count on the workspace pill (`dev ●2`), `notice.posted` / `notice.resolved` events with `quickterm notices list`, and the activity log. Counts are panes that need you, not notices.
- After you focus a blocked pane and press a key, the banner and the Dock badge clear; the pane mark and the pill count stay until the agent's hook confirms it moved on.
- The engine's own path to macOS notifications is gone: OSC 9/99/777, command-finished and the bell all go through the center, so nothing fires twice. `[notifications] command-finished` replaces the engine's `notify-on-command-finish` keys, which are no longer consulted.
- Notice bodies can carry a command line, so they are redacted for callers without the token on every control-plane surface and kept out of the system log, exactly like browser URLs.

### Configuration
Two new groups, `[agents]` and `[notifications]`, with a new list-valued key kind (`enabled = ["claude-code", "codex", "gemini"]`). Defaults: detection on, `hook-detail = "lifecycle"` (the tool-by-tool tier is opt-in, one process per tool call), `auto-install-hooks = "ask"`, system notifications only for inactive panes, a bare bell ignored.

### Honest limits
- Verified end to end with recorded hook payloads replayed through the installed script inside a pane, and against a process stand-in for the scan. What only a real session proves: that the installed Claude Code, Codex and Gemini accept the entries and fire the hooks with the pane's environment. Please report anything that does not light up.
- Codex's and Gemini's terminal-notification wording is not in their documentation, so their OSC fallback tables ship empty; hooks are the primary path and do not need them.
- macOS grants notification permission only to an app launched through Finder or `open`; the first such launch asks once.
- herdr protocol compatibility (`[agents] herdr-compat`) is designed but not yet built.
