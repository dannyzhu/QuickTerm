## QuickTerm 1.6.6

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

### The self-test now behaves like a real agent
1.6.5's `quickterm notices test` raised its alarm with "composed" evidence, which a keystroke *resolves* — so the moment you typed the next command the Dock badge cleared, and it only ever flashed for about a second. That made a working badge look broken.

The self-test now raises its alarm with the same "report" evidence a real agent hook uses. A keystroke *quiets* it (the banner steps back) but does not clear it, so:

- the **Dock badge stays up for the full 15 seconds**, whether or not you type — long enough to actually look at it;
- to see the **banner**, run `quickterm notices test` and switch to another app within those 15 seconds (a banner is held while QuickTerm is the app you're looking at, by design);
- with `--json`, the `banner` line now says exactly that.

This is a fix to the diagnostic only. Real agents already raised their alarms this way, so nothing about how a real agent lights the badge or banner changes.

### If a real notification still does not appear
The diagnostic log (`[notifications] diagnostic-log = true`, written to `~/Library/Logs/QuickTerm/diagnostics.log`) records every badge set and every banner presented, skipped or refused, with the macOS authorization at each step. A `[badge] Dock badge → 1` line with no badge on screen points at the Dock or a Focus mode; a `[banner] refused` line points at macOS authorization.
