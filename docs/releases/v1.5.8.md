## QuickTerm 1.5.8

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

Three intermittent interaction bugs, all found by measurement rather than guesswork.

### Fixes
- **Cmd+clicking an http link in a terminal sometimes opened the system default browser** instead of a QuickTerm browser pane. The engine's open-URL callback resolved the destination through the clicked pane's own view hierarchy only, and a pane is detached from its window for a frame or two whenever SwiftUI rebuilds the layout — and QuickTerm replays synthetic clicks into panes without checking for that. A pane now remembers its owning window controller (a torn-down screen is excluded), and link routing falls back through owner → key → main → any terminal window before the system opener is ever considered.
- **The hand cursor could persist after Cmd was released, and the focused terminal would then refuse to scroll.** One latched boolean caused both: the Cmd-held state had a single writer — a local event monitor, which structurally cannot see a Cmd release delivered to another app (Cmd+Tab, Cmd+Space, Cmd+Shift+4, Cmd+H) — so the Cmd-drag overlay stayed mounted, supplying the cursor and swallowing the wheel. That state now heals itself (cleared on deactivation, resynced from the real modifier flags on reactivation and on mouse/scroll events), and the overlay only covers a pane during an actual drag and no longer intercepts scrolling.
- **An extension's toolbar icon could stop responding after a while.** `WKWebExtensionContext.focusedWindow` is a cached value that only the app can update, and QuickTerm reported it from a single place — so clicking a toolbar button (which does not change first responder) left extensions querying the wrong pane. The current window is now reported from every path that changes it, the click resolves the tab, action and enabled state at click time, the button is never disabled (a disabled button swallows clicks silently), and a suspended MV3 background worker is explicitly woken before the action is dispatched. Extension background-load failures are also logged now instead of being silently discarded.

### Known limit
Scheme-less host-like links in terminal output (`github.com/owner/repo`) are still treated as relative paths by the engine's link detection, so Cmd+clicking them does nothing. Normalising them without mis-firing on real relative paths is a separate change.
