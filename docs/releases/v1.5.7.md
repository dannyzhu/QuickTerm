## QuickTerm 1.5.7

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

Extension panels that live inside a web page (Stylish's sidebar is the reference case) now work properly: they see the extension's real data and its signed-in account.

### Fixes
- **Extension panels showed no data.** WebKit partitions web storage by top-level site, and an extension page injected as an iframe into an ordinary page counts as third party — so its IndexedDB was a separate, empty store, not the one the extension's background and its own pages use. QuickTerm now bridges IndexedDB from such frames to the extension's background, which owns the real store. (Stylish's "My Styles" went from empty to listing the installed styles.)
- **Extension panels showed you as signed out even when you were signed in.** QuickTerm masquerades as Safari for websites; WebKit was handing that spoofed User-Agent to the extension's own in-page frames too, while the same extension's background saw WebKit's real UA — so the two halves of one extension believed they were in different browsers, which Chrome never does. Extension-origin documents (in-page panels, extension tabs, `window.open`ed extension pages) now always see the same User-Agent as their background. Firebase-based sign-in in extension panels works again as a result.
- Bridged IndexedDB transactions are now real transactions: requests issued together run in one background transaction, so `abort()` and a failing request roll back the writes before them, and `versionchange` reaches the frame.

### Known limits of the bridge
One batch of requests = one background transaction (a read-then-write across separate callbacks is not atomic); cursors are a snapshot capped at 5000 rows; `Blob`/`File`/`ArrayBuffer` values do not cross the bridge; `localStorage`/`sessionStorage` are synchronous and stay partitioned per top-level site. An in-page extension frame is also an ordinary CORS client (unlike the background, host permissions do not exempt it), which is WebKit's behaviour, not something QuickTerm changes.
