## QuickTerm 1.5.6

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

**Session archive upgrade**: `state.json` moves to v5 on first launch and your previous archive is kept beside it as `state.pre-v5.json`. QuickTerm 1.5.5 and earlier cannot read v5 (they will refuse it and start fresh rather than damage it).

### Highlights
- **Screens (multiple windows)** — a *screen* is a QuickTerm window with its own workspaces, status bar, floating layer and Scratchpad, so you can put one on each display and work independently. Everything is in the **Window** menu (no keybindings, since you rarely need them): open a screen on the current or a chosen display, move this screen to another display (handy — the window has no title bar to drag), show it on all Spaces, close it. The display submenus are rebuilt each time they open, so hot-plugged, Sidecar and virtual displays appear immediately.
- **One-click restore** — relaunching brings back every screen on the display it was on, with its window position, workspaces, layouts, floating panes, focused pane, each terminal pane's working directory and each browser pane's open tabs. State is now written continuously (debounced) instead of only at quit, so a crash or force-quit no longer loses the session.
- Per-window non-native fullscreen: one screen leaving fullscreen no longer restores the menu bar while another is still fullscreen, and closing a fullscreen screen releases exactly what it took.
- Panes created in a window on a secondary display now pick up that display's backing scale instead of the main display's.

### Fixes
- **Extensions could not receive messages from web pages.** WebKit implements Chrome's `externally_connectable` channel but exposes it to pages only as `browser.runtime`; every Chrome-built site checks for `chrome` first, so the handshake silently did nothing — Stylish, for one, never received the login token from userstyles.org and always showed you signed out. Pages matching an installed extension's `externally_connectable.matches` now get a minimal `chrome.runtime` alias (messaging only; delivery and permissions stay WebKit's).
- A newly created browser pane could sit half outside the viewport in the scrolling layout (it looked like the pane had the wrong width). Newly inserted columns are now revealed by identity instead of waiting for focus, which for a browser pane arrives late via its WKWebView. Fixes two older bugs with it: changing "visible columns" could leave the strip scrolled off-screen, and inserting while zoomed skipped the reveal entirely.
- Theme changes, config reloads and browser extensions now reach every window rather than only the most recently created one; "equalise all" no longer equalises other screens; dragging a pane between windows is explicitly refused instead of silently doing nothing.

### Known limits (macOS, not QuickTerm)
- A window **cannot be sent to a specific Space** — no public API. New screens open on the Space you are on; a Mission Control drag is remembered by macOS but cannot be restored by us.
- While any screen is in non-native fullscreen, the Dock and menu bar hide on **every** display, because `presentationOptions` is process-wide.

## QuickTerm 1.5.6（中文）

通用二进制（Apple Silicon + Intel，macOS 15.4+），ad-hoc 签名，首次打开请按 README「安装」一节处理 Gatekeeper。

**存档升级**：`state.json` 首次启动会升到 v5，旧档原样留在同目录的 `state.pre-v5.json`。1.5.5 及更早的版本读不了 v5（会拒绝并重新开始，不会破坏它）。

### 亮点
- **屏幕（多窗口）** —— 一个「屏幕」就是一个 QuickTerm 窗口，有自己的工作区、状态栏、浮动层和 Scratchpad，每台显示器摆一个、互不干扰。入口全在 **Window 菜单**（不占快捷键）：在当前或指定显示器上新建屏幕、把这个屏幕移到另一台显示器（窗口没有标题栏可拖，这条尤其有用）、在所有桌面显示、关闭屏幕。显示器子菜单每次打开时重建，热插拔、Sidecar 与虚拟显示器都能立刻出现。
- **一键复原** —— 重开应用会还原每个屏幕、它原来所在的显示器与窗口位置，以及各自的工作区、布局、浮动 pane、焦点 pane、每个终端 pane 的目录、每个浏览器 pane 打开的标签页。存档改为持续写入（防抖），不再只在退出时写一次，崩溃或强制退出不会再丢会话。
- 非原生全屏按窗口记账：一个屏幕退出全屏，不会把另一个还在全屏时的菜单栏放出来；关闭全屏屏幕正好释放它占用的那份。
- 在非主显示器的窗口里新建的 pane，会按那台显示器的缩放渲染，不再固定按主显示器。

### 修复
- **网页发给扩展的消息收不到**。WebKit 实现了 Chrome 的 `externally_connectable` 通道，但在网页里只把入口挂成 `browser.runtime`；而 Chrome 生态的站点一律先看有没有 `chrome`，于是握手静默失败——比如 Stylish 永远收不到 userstyles.org 递过来的登录 token，一直显示未登录。现在匹配到已装扩展 `externally_connectable.matches` 的网页会拿到一层最小的 `chrome.runtime` 别名（只有消息，投递与鉴权仍归 WebKit）。
- scrolling 布局下新建的浏览器 pane 可能有一半挂在视口外（看起来像「宽度不对」）。新插入的列改为按身份滚出视野，不再等焦点落地（浏览器 pane 的焦点要多走一跳 WKWebView，来得晚）。连带修掉两个老问题：改「每屏可见列数」后整条带会停在内容外面；zoom 状态下插列压根不会滚。
- 主题切换、配置重载、浏览器扩展现在都会作用到每一个窗口，而不只是最后创建的那个；「全部等分」不再连别的屏幕一起等分；跨窗口拖 pane 明确拒绝，不再静默失败。

### 已知限制（来自 macOS，不是 QuickTerm）
- **窗口无法被程序放到指定的虚拟桌面（Space）** —— 公开 API 没有这个能力。新屏幕只会开在你当前所在的桌面；你用 Mission Control 拖过去之后 macOS 会记住，但我们无法在重启后复原。
- 只要有任一屏幕处于非原生全屏，Dock 与菜单栏会在**所有**显示器上隐藏，因为 `presentationOptions` 是进程级的。
