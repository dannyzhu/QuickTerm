## QuickTerm 1.6.0

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

Two headlines. The interface learned to **name things**: a pane title drawn into the pane's own border, a name on a workspace pill, both settable from the command line. And the project went **English-first with a bilingual UI**: the CLI, every code comment, every log message and every document are English, while the app itself ships in English and Simplified Chinese and follows your system language.

### Naming what you are looking at
- **Pane titles on the frame.** A title you set — right-click ▸ Change Terminal Title, or `quickterm pane set -t t7 --title 'build · web'` — is drawn into the pane's 2px top border, fieldset-legend style. Only titles you set: a title the shell reports over OSC changes on every command and would make the border twitch. At most 20 characters (an ellipsis counted inside them), never touching the top-right corner, always leaving at least two characters of border to its right, and drawn not at all when the pane is too narrow for one character. `[appearance] pane-title = false` turns it off.
- **Workspace names.** Right-click a workspace pill to name it, or `quickterm workspace set -t 1:4 --title dev`. The name belongs to the *slot*: clearing the workspace, closing every pane in it and `spec apply --replace` all leave it alone. Names survive a restart, ride through `spec dump | apply`, and show in the status bar in place of the number — with the whole row falling back to numbers at once when they would crowd the clock. `[appearance] workspace-title = false` turns it off.

### Bilingual UI, English everything else
- **`[general] language = auto | en | zh`.** `auto` follows the system. The catalog is standard `.lproj` with English as the base language, so a key missing from Chinese falls back to the English sentence rather than showing a raw key, and a build-phase linter rejects a missing key, a dead key, a concatenated lookup or Chinese left in an English value.
- **The command line speaks English** — `--help`, `describe --json`, errors, hints and the generated MCP tool descriptions — because the people reading it are increasingly agents. Logs, wire identifiers, config keys and pane handles are English in both languages. Text macOS draws itself (privacy prompts, standard AppKit and WebKit dialogs) follows macOS, not this key.
- Code comments, log messages, the porting notes, the design spec, the agent docs and this file: English.

### New command-line surface
- `quickterm browser open | goto | reload | close` — the tabs inside a browser pane. `-t` names the pane, `--tab` picks the tab (1-based index, `#id` prefix, `@active`, `@last`), and closing the last tab closes the pane, exactly as ⌘W does.
- `quickterm pane capture-text` — read what a terminal pane is showing. Off by default, requires the per-launch token, and asks the user once per calling process: a viewport can hold a token you just exported or a password you have not submitted yet. There is deliberately no "reading your own pane is free" exemption.
- `quickterm pane set --title` / `quickterm workspace set --title`, and `-t 'title:~<regex>'` to address a pane by the name you gave it.
- **`--cwd` that cannot be used is no longer silent.** A protected directory (`~/Desktop`, `~/Documents`, `~/Downloads`) without the Files and Folders permission used to open the pane somewhere else and report plain success. The reply now carries a `cwd_denied` warning naming the path, the reason and the fix; `--require-cwd` turns it into an error that creates nothing.

### Fixes
- **Fullscreen video went black after pause then play**, audio still playing, a right-click still producing a normal page menu on the black. The pane pinned the web view with Auto Layout constraints, and when WebKit moves that view into its own fullscreen window and sizes it by hand, our next layout pass wrote the pane's inline size back over WebKit's fullscreen frame — the page then sat at about 500×600 in the corner of a black backdrop. Pause-then-play is a reliable trigger because a video site changes its title, which rebuilds the tab bar, which is a layout pass. The web view now owns its own frame.
- Closing a tab, switching tabs or swapping a web view while WebKit holds it in element fullscreen no longer blanks the fullscreen window; the command line gets a real error telling it to leave fullscreen first, instead of a success for something that did not happen.
- The confirmation dialog for `quickterm pane close` on a multi-tab browser pane promised that only the current tab would close. That is true of ⌘W and false of the command, which closes the pane and every tab in it.
- The cheat sheet and the confirmation dialog drew Chinese action descriptions in an English UI.

### Errors: read the code, not the exit
`exit 5` used to mean six unrelated things. It now decomposes: `denied` is a human pressing Deny and nothing else, `disabled` is a switch in `[control]`, `cwd_denied` is `--require-cwd` (spelled exactly like the warning that rides on a successful reply), `limit` is a structural cap or floor, and `interactive_action` is a command that needs a keyboard. Exit codes stay coarse on purpose; the code is the fine signal, and `describe --json` now lists the warnings, the mutation-envelope fields and `--start` so an agent can branch on all of it after one read.

### Also
- A person running a command by hand gets `Error:` and `Hint:` before the JSON envelope; a pipe or `--json` still gets JSON only.
- `docs/agents/AGENTS.quickterm.md` is a drop-in `AGENTS.md`: copy it into your project root and your coding agent can drive QuickTerm. It told agents a user Deny was exit 4; it is 5.
- One rulebook for titles (length, control characters, trimming, truncation) instead of nine copies that had already drifted: `pane set --title '   '` used to pin a pane to an invisible title the shell could never update again.
- `state` reports `titleSet`, so a caller can tell a title you pinned from the one the shell is reporting.

### Honest limits
- Element fullscreen is where WebKit and an embedding app disagree about who owns a view's frame. The fix is measured and tested, but if you find another way to make a fullscreen video misbehave, that is worth a report.
- Three localization tests read the source tree and skip on an ad-hoc-signed build under `~/Documents`; the same invariants run as a build phase on every build.
- `same-as-english` values in the Chinese catalog are marked as deliberate rather than being caught as untranslated.
