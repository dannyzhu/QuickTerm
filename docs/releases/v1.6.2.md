## QuickTerm 1.6.2

Universal binary (Apple Silicon + Intel, macOS 15.4+), ad-hoc signed — see the README's *Install* section for the one-time Gatekeeper step.

The first real session with 1.6.1's agent awareness turned up two things, and this release fixes both.

### The agent status bar
- The 10pt text-only strip overlapped the pane's title badge and was easy to miss. It is now a **status bar**: a filled band across the pane's top padding, 11pt semibold text on a background — `[agents] strip-background` for idle / working / done, `[agents] strip-attention` for an agent that is blocked or failed, `[agents] strip-text` for the text (`#rrggbb`; defaults from the Tokyo Night palette). `done` still flashes green and fades back.
- The bar carries the pane's own title, so **the title badge on the border stands down while the bar is up** — nothing overlaps — and returns unchanged when the agent is gone.
- Still drawn inside the padding, still never a resize: 13pt tall at the default `pane-padding` of 14 (exactly what 11pt semibold glyphs need, measured), drawn from `pane-padding = 12` up, and drawn *under* the frame so the red pane mark stays whole.

### macOS notifications that never arrived
- If macOS has notifications **denied** for QuickTerm, no banner can ever reach you — and until now the app only logged it. It now tells you: once per launch an app-level notice appears in `quickterm notices list` (`appNotices`), the reply carries `systemNotifications: authorized | denied | notDetermined | unavailable`, and the activity log records it. The fix is yours to make: System Settings ▸ Notifications ▸ QuickTerm ▸ Allow.
- The Dock badge was measured, not assumed: on an instance launched through LaunchServices with notifications denied, `lsappinfo` reports the badge label `1` while a pane needs you and clears it on `notices ack`. macOS does not suppress the Dock badge for a denied app.

### Also
- `--config-file`, `--state-file` and `--control-socket` launch arguments (same meaning as the `QUICKTERM_*` variables, arguments win), so a second instance can be started through `open -n -a … --args` — the only launch macOS treats as a real app for notifications. Documented in both READMEs.
- `notices list --help`, the MCP schema and the agent docs describe the new fields.
