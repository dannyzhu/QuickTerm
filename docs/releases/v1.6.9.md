## QuickTerm 1.6.9

Universal binary (Apple Silicon + Intel, macOS 15.4+), signed with a Developer ID and notarized by Apple. From 1.6.8 on, QuickTerm updates itself: this release arrives through the status bar icon.

### Fixes
- **A pane no longer keeps saying "Claude Code · done" after Claude Code has exited.** Two things went wrong at once. The agent's `Stop` and `SessionEnd` hooks run asynchronously and can reach QuickTerm in either order; when the `Stop` came in after the `SessionEnd`, it rebuilt a status that nothing could take down again. And the process scan, which is the fallback that releases a status when the agent's process goes away, never saw Claude Code's native install at all: `~/.local/bin/claude` is a symlink to `~/.local/share/claude/versions/<version>`, and macOS names the process after the target, so the rule file's `process = ["claude"]` never matched. Now a session that ended stays ended for a few seconds (a late `Stop` or "task complete" text of that session is dropped, while an approval prompt always gets through), and rule files gain `process-path`, a fragment of the executable's path, so the native install is recognised.

### Diagnostics
- Holding `⌘` over a pane should show the grab cursor and let you drag the pane; on one machine it does nothing, and the cause is not known yet. QuickTerm now logs every change of that state, and what fed it, under the `modifiers` log category, so `log stream --level debug --predicate 'subsystem == "dev.danny.quickterm" AND category == "modifiers"'` shows where the chain breaks.

### For people building from source
- Agent rule files (`Resources/agents/*.toml`) accept `process-path = [...]` next to `process`: fragments matched against the resolved executable path. The scan still reads a process's environment only when a rule names it.
